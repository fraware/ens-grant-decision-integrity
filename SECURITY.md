# Security and sensitive disclosures

This repository contains governance specifications and examples, not production secrets.

If a report would expose applicant-confidential material, security-sensitive evaluator configuration, private keys, credentials, or exploitable infrastructure details, do not open a public issue containing those details. Contact the repository maintainer privately through an appropriate channel and provide only the minimum information needed to reproduce the concern.

Public issues are appropriate for threat-model gaps, protocol-design concerns, disclosure-classification problems, and non-sensitive implementation feedback.
